# Design System — "Aurora Glass"

> **Status:** Adopted 2026-09-14 · **Depends on:** [06-frontend-architecture.md](./06-frontend-architecture.md) §6, [02-technical-prd.md](./02-technical-prd.md) §8

Direction **04** of the five in `Samples/`, chosen by Mehrang. Frosted translucent
surfaces over a fixed gradient mesh, with light and dark equally first-class — the mesh carries the
mood, so the surfaces stay nearly colourless in both.

The implementation is `frontend/src/styles/tokens.css`. **That file is the system**; this document
explains the decisions behind it and the rules for extending it.

---

## 1. The one rule

**Every themeable value is a CSS custom property, and no component hard-codes a colour.**

```css
/* ✅ */ color: var(--color-primary);
/* ❌ */ color: #6d4aff;
```

This is not a style preference. The entire cosmetics system (06 §6.1) is *runtime variable
swapping*: `themeStore` sets a property on `document.documentElement` and the whole app changes with
no re-render. A hard-coded hex is a value that cannot be themed, cannot be swapped for a cosmetic,
and will be wrong in dark mode — and there is no lint rule that can catch it, so it is a review
responsibility.

---

## 2. Token reference

All tokens live in `:root`; the dark palette re-declares only what changes under
`:root[data-theme="dark"]`.

### 2.1 Colour

| Token | Light | Dark | Use |
|---|---|---|---|
| `--color-bg` | `#eef1f8` | `#0c0a18` | The page. Painted behind the mesh |
| `--color-surface` | `white 62%` | `white 6.5%` | The default glass panel |
| `--color-surface-raised` | `white 78%` | `white 10.5%` | A panel that should read as *above* the others — the resume card, a modal |
| `--color-surface-sunken` | `white 34%` | `white 3.5%` | Inputs, wells, the game felt area |
| `--color-border` | `white 70%` | `white 13%` | The glass edge. Deliberately light, not dark |
| `--color-border-strong` | `#5d4f8c 28%` | `white 26%` | Where a border must actually be seen — input outlines, the timer track |
| `--color-text` / `--color-text-muted` | `#171429` / `#5c5478` | `#f3f1fb` / `#a79fc6` | Body and secondary |
| `--color-primary` | `#6d4aff` | `#a78bfa` | Actions, the acting seat, links |
| `--color-accent` | `#ff5c8a` | `#ff7aa2` | The gradient's second stop; never used alone for meaning |
| `--color-success` / `--color-danger` / `--color-warning` | | | State, each with a `-soft` background pair |
| `--color-coin` / `--color-gem` / `--color-ticket` | | | The three wallet assets, each with its own identity in every surface |

Each semantic colour has a `-soft` companion (`--color-danger-soft`) for backgrounds. **Use the pair
together** — `--color-danger` text on `--color-danger-soft` — rather than inventing an opacity.

### 2.2 Table semantics

`--seat-ring-active`, `--seat-ring-idle`, `--timer-ok`, `--timer-warn`, `--timer-danger`.

Separate from the generic palette on purpose: "the seat whose turn it is" and "the timer is nearly
up" are table concepts, and a future cosmetic may want to change one without the other.

### 2.3 Type

| Token | Value | Notes |
|---|---|---|
| `--font-display` | Outfit → Vazirmatn → system-ui | Headings, numbers that are *read as figures* |
| `--font-body` | DM Sans → Vazirmatn → system-ui | Everything else |
| `--font-numeric` | DM Sans, tabular | Balances, timers, scores |
| `--text-xs … --text-3xl` | 0.75 → 2.75 rem | A 1.15–1.3 ratio; no size outside the scale |

**Persian swaps the whole stack.** `:root:lang(fa)` sets all three to Vazirmatn, because Outfit and
DM Sans have no Arabic coverage — leaving them first would fall back per-glyph and mix two faces
inside a single word.

Fonts are **self-hosted** (`frontend/public/assets/fonts/`, generated by
`frontend/scripts/fetch-fonts.mjs`) with per-subset `unicode-range` and `font-display: swap`. No
page load reaches a third party, and the container builds offline.

### 2.4 Space, shape, motion

`--space-1 … --space-8` (0.25 → 3.5 rem) · `--radius-sm/md/lg/full` · `--shadow-1/2/3` ·
`--dur-fast/base/slow` + `--ease`.

`--blur: 18px` drives the glass. `--focus-ring` is a two-layer `box-shadow` so focus is visible on
both light and dark surfaces.

### 2.5 Cosmetics

`--felt-color`, `--felt-pattern`, `--card-back-image`, `--card-face-set`, `--card-radius`,
`--card-aspect`, `--anim-card-deal`, `--anim-card-flip`.

Written by `themeStore`'s single `subscribeWithSelector` subscription. **No component touches
`document.documentElement`** — that store is the only DOM writer in the app.

## 3. Components

### 3.1 The glass primitive

```css
.glass {
  background: var(--color-surface);
  border: 1px solid var(--color-border);
  backdrop-filter: blur(var(--blur)) saturate(150%);
  box-shadow: var(--shadow-1);
}
```

Global, in `global.css`, rather than a CSS Module — because it is a **material**, not a component.
The topbar, a game card and the reward panel are all made of it.

> ⚠ **`backdrop-filter` is the cost centre.** It forces compositing on every panel that uses it.
> Budget ~12 glass surfaces per screen. It is dropped entirely below 560 px (where the backdrop is
> barely visible behind a full-width panel) and under `prefers-reduced-motion`.

### 3.2 Buttons

| Variant | Use |
|---|---|
| `primary` | The one action the screen exists for. Gradient fill. **At most one per view** |
| `quiet` | Secondary actions. Bordered, sunken background |
| `ghost` | Toolbar and icon buttons |
| `danger` | Destructive, with a confirmation behind it |

`min-block-size: 46px` on every button and `48px` on every input, so no control is below the 44 px
touch-target minimum.

### 3.3 States every list must have

Loading (**skeletons**, not a spinner — the layout must not jump when data lands), error (with a
retry that actually refetches), and empty (with a next action). A screen missing one of these is
incomplete, not polished-later.

## 4. RTL — correctness, not polish

**Logical properties only.** `margin-inline-start`, `padding-block`, `inset-inline-end`,
`border-start-start-radius`. Enforced by `stylelint-plugin-logical-css`, and there is a test that
proves the plugin actually rejects `margin-left` rather than merely being listed in the config.

**There is no RTL stylesheet.** The layout mirrors because it is built from logical properties, full
stop. If something does not mirror, the fix is to find the physical property, never to add a
`[dir="rtl"]` override.

| Mirrors | Does **not** mirror |
|---|---|
| Seat ring, hand fan, chat side, turn arrow, nav, forms, the timer ring's drain direction | **Chess board** (a1 stays bottom-left), **Sudoku grid**, card faces and pips, clockwise trick direction |

The exceptions are wrapped in `dir="ltr"` islands (`.ltr` in `global.css`). Mirroring a chess board
breaks notation for everyone who reads it, which is every chess player.

Two smaller rules that come from the same place:

- `letter-spacing` and `text-transform: uppercase` are **removed under RTL** — Persian has no case,
  and letter-spacing breaks its joining behaviour.
- Latin-by-nature values (emails, invite codes, ids) get `dir="ltr"` inside an otherwise RTL form,
  or the `@` and dots reorder visibly.

## 5. Numerals and dates

`formatNumber` / `formatDate` in `frontend/src/lib/format.ts`.

- **Display only.** A number a human reads as a *quantity* converts; a string that happens to
  contain digits never does. An invite code in Persian digits is untypeable and unsearchable.
- `numeralSystem: 'auto'` follows the language; `latin` and `persian` override it in both
  directions.
- Dates are Jalali for `fa` via `Intl.DateTimeFormat({ calendar: 'persian' })` — never a hand-rolled
  converter, which is a classic source of off-by-one-day bugs around Nowruz.
- **Multipliers keep their fraction.** `maximumFractionDigits` defaults to 0 (right for coins), and
  the reward breakdown passes 2 — a 1.5× premium rendered as "×2" makes the arithmetic contradict
  the total it explains.

## 6. Accessibility

- Decorative icons are `aria-hidden`; an icon that is a control's only content takes a `title`,
  which becomes its accessible name. **No emoji as icons** — they render differently per platform,
  cannot inherit `currentColor`, and are read aloud as their Unicode name.
- Colour is never the only differentiator. The acting seat gets a ring *and* a lift; the
  high-contrast card face set adds suit letters.
- Seat and turn changes announce over `aria-live="polite"`, from the same i18n keys the chat log
  uses.
- A "coming soon" card is `aria-disabled` and focusable rather than removed, so it advertises the
  game to a screen-reader user too.
- Target: WCAG 2.1 AA contrast on all four felt colours in both themes, checked per milestone.

---

## 7. Adding to the system

1. **Need a colour?** Add a token, in both palettes. Never a hex in a component.
2. **Need a size?** Use the scale. If nothing fits, the scale is wrong — change it once.
3. **Need a one-off?** You almost certainly need a variant of an existing component.
4. **Adding a game?** Its card needs no design work: `GameCard` renders from `GET /games` and falls
   back to a generic icon for a slug it has never seen. That is P5 on the client.
